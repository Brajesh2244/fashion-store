1. Overall Project Architecture & Package Structure

The Fashion Store project is built using Jakarta EE Web Technologies (Java Servlets & JSP) running on a relational MySQL Database accessed via JDBC (Java Database Connectivity).

⚠️ CRITICAL ARCHITECTURAL DIRECTIVE (NO SERVICE LAYER)
This project DOES NOT USE A SERVICE LAYER. The Servlets (Controllers) directly instantiate and invoke the Data Access Object (DAO) implementation classes (e.g., UserDAO userDAO = new UserDAOImpl();). There is no intermediate service interface or class present in the codebase.

2. Core Component Roles & Beginner's Layer Distinctions

To understand this Java web application, you must distinguish between the 6 distinct component types used in the project:

1. DAO Interface Java Interface

Example: UserDAO.java

A rulebook or contract. Contains only method signatures without code bodies (e.g. boolean registerUser(User user);). It defines what database actions can be taken without specifying how.

2. DAO Implementation Java Class

Example: UserDAOImpl.java

The actual worker. Implements the DAO interface (implements UserDAO), opens JDBC connections, executes SQL queries against MySQL, and packages SQL rows into Java objects.

3. POJO / Model Data Carrier

Example: User.java, CartView.java

Plain Old Java Object. A container with private variables (e.g., userId, email), constructors, getters, and setters. Holds data in memory while traveling between database and view.

4. Servlet / Controller HTTP Router

Example: LoginServlet.java

Extends HttpServlet with @WebServlet("/login") annotation. Listens for browser requests (doGet/doPost), coordinates DAO calls, manages HTTP Sessions, and decides which JSP to display.

5. Connection Layer Database Manager

Example: DBConnection.java

Utility class containing static method DBConnection.getConnection(). Loads MySQL JDBC Driver and opens active connections to jdbc:mysql://localhost:3306/fashion_store.

6. JSP / View HTML Renderer

Example: products.jsp

JavaServer Pages inside WEB-INF/views. Combines HTML with Java Expression Language (EL) / JSTL tags to output dynamic web pages to the user.

Deep Dive: What a POJO/Model Class Does & How Objects Are Used

A POJO (Plain Old Java Object) is a clean Java class that maps directly to database tables or combined query views. It does not contain complex business logic or SQL statements; its sole job is to hold data in structured variables.

Visualizing Data Carrier POJOs in Fashion Store
  • Entity POJOs: User (maps to users table), Product (maps to products table), ProductVariant (maps to product_variants table), Cart, CartItem, Order, OrderItem.
  • DTO / View POJOs: CartView.java and OrderItemView.java are specialized view models. For instance, CartView combines data joined from 3 database tables (cart_items, product_variants, and products) into a single object holding product name, brand, image URL, size, price, quantity, and calculated subTotal.
How Objects Move Between Layers (Data Pipeline)

1. Servlet to DAO (Writing Data): User submits a form. RegisterServlet reads raw form strings via request.getParameter(), creates a new User() POJO, populates it using setters (user.setFullName(...)), and passes the user object to userDAO.registerUser(user).

2. DAO to Database (SQL Bindings): UserDAOImpl receives the User POJO, extracts values via getters (user.getFullName()), and inserts them into PreparedStatement parameters (?).

3. Database to DAO (Reading Data): UserDAOImpl executes executeQuery(), receives a SQL ResultSet, and invokes helper mapResultSetToUser(resultSet) which reads column values (e.g. resultSet.getString("email")) and creates a populated User object.

4. DAO to Servlet to JSP (Rendering Data): UserDAOImpl returns the User object to LoginServlet. The Servlet attaches it to the request scope via request.setAttribute("user", user) or session scope via session.setAttribute("loggedInUser", user). Finally, login.jsp reads fields using Expression Language: ${sessionScope.loggedInUser.fullName}.

JDBC Object Roles & Resource Management

Every DAO method uses Try-With-Resources blocks to manage JDBC objects. This automatically closes database resources (Connection, PreparedStatement, ResultSet) even if an exception occurs, preventing connection leaks.

JDBC Class / Interface Exact Code Usage in Project Purpose in Execution Flow
java.sql.Connection Connection connection = DBConnection.getConnection(); Establishes active physical socket session with MySQL server.
java.sql.PreparedStatement PreparedStatement preparedStatement = connection.prepareStatement(SQL); Pre-compiles SQL queries with positional parameters (?). Protects against SQL Injection attacks and handles parameterized data insertion (e.g. ps.setString(1, email);).
java.sql.ResultSet ResultSet resultSet = preparedStatement.executeQuery(); Holds the tabular data returned by MySQL SELECT queries. Acts as a cursor pointing to data rows (e.g., while(resultSet.next()) { ... }).
Generated Keys connection.prepareStatement(SQL, Statement.RETURN_GENERATED_KEYS) Used in OrderDAOImpl.placeOrder() to capture the auto-incremented primary key (order_id) generated by MySQL after inserting a new order row.
Web Objects & Context Variables Reference
HttpServletRequest & HttpServletResponse
  • request.getParameter("key"): Retrieves string inputs sent from HTML form inputs or URL query parameters (e.g. ?id=5).
  • request.setAttribute("key", object): Attaches data (e.g. List<Product>) to request scope for JSP rendering.
  • request.getRequestDispatcher("/WEB-INF/views/x.jsp").forward(...): Server-side dispatch that keeps request data intact.
  • response.sendRedirect(request.getContextPath() + "/url"): Browser-side redirect commanding user browser to make a fresh GET request.
HttpSession Management
  • request.getSession(false): Retrieves existing HTTP session without creating a new one if missing. Used for login authentication checks.
  • session.setAttribute("loggedInUser", user): Stores logged-in user object globally across multiple browser requests.
  • session.setAttribute("userId", user.getUserId()): Quick access attribute for cart and order queries.
  • session.invalidate(): Used in LogoutServlet.doGet() to destroy the session upon logging out.

7. Complex Order Placement & Checkout Transaction Trace

The Place Order operation is the most critical workflow in the project. It involves multi-table coordination across 5 DAOs (Cart, CartItem, Order, OrderItem, ProductVariant) to process checkout, verify stock, insert orders, decrease inventory, and clear the cart.

Multi-Step Execution Pipeline in PlaceOrderServlet.doPost()
1
Authentication & Cart Retrieval
PlaceOrderServlet verifies user session, gets userId, calls cartDAO.getCartByUserId(userId), and fetches detailed cart items via cartItemDAO.getCartView(cart.getCartId()).
⬇️
2
Order Total Calculation & Order POJO Creation
Iterates over List<CartView> items, calculates totalAmount = totalAmount.add(item.getSubTotal()). Instantiates new Order() and populates: userId, totalAmount, shippingAddress, paymentMethod, and status = "PLACED".
⬇️
3
Insert Master Order Record & Retrieve Generated Key
Calls orderDAO.placeOrder(order). OrderDAOImpl executes SQL: INSERT INTO orders(user_id, total_amount, shipping_address, payment_method, status) VALUES(?,?,?,?,?) with Statement.RETURN_GENERATED_KEYS. Returns newly generated order_id (int).
⬇️
4
Loop Items: Stock Check, Save OrderItem & Update Inventory Stock
For each CartView item in cart:
a) Checks stock: int availableStock = productVariantDAO.getAvailableStock(item.getVariantId()) (SELECT stock FROM product_variants WHERE variant_id=?). If insufficient, redirects to checkout error.
b) Saves order line item: Instantiates new OrderItem() (orderId, variantId, quantity, price) and calls orderItemDAO.addOrderItem(orderItem) (INSERT INTO order_items(order_id, variant_id, quantity, price) VALUES(?,?,?,?)).
c) Decrements stock: Calculates newStock = availableStock - item.getQuantity() and calls productVariantDAO.updateStock(variantId, newStock) (UPDATE product_variants SET stock=? WHERE variant_id=?).
⬇️
5
Clear Shopping Cart
Calls cartItemDAO.clearCart(cart.getCartId()). Executes SQL: DELETE FROM cart_items WHERE cart_id=?.
⬇️
6
Redirect to Order Success Confirmation
Redirects browser: response.sendRedirect(request.getContextPath() + "/order-success?orderId=" + orderId);. OrderSuccessServlet.doGet() loads order details via orderDAO.getOrderById(orderId) and forwards to /WEB-INF/views/order-success.jsp.
